# 国龙销售工具 · 公开源码版

基于 Electron、SQLite/SQL.js 和 ExcelJS 的本地销售工具，公司版和公开版共用这一份程序源码，当前功能版本为 2.22.0。

支持产品与配件录入、搜索、资料管理、库存导入，以及用 Excel 模板生成合同和报价单。

CCC设备详情支持独立的能效检测报告资料类型，左键复制、右键添加或替换、删除前确认。公开版不包含任何公司报告或产品映射。

## 图片目录

图片按文件夹管理。设备图片位于 `images/equipment/<类别>/<设备名称>/`，同名设备的不同型号使用同一目录；配件图片位于 `images/parts/<配件品类>/`，容量、功率等规格共用目录，例如折叠锅盖、八字平躺搅拌、控制器、接触器。目录分组不改变各商品的图片映射或相册同步范围。

新增、编辑或复制商品时，先填写商品名称，再选择图片。选图器自动创建并打开对应目录；选到其他目录的图片会归档到目标目录。选图后修改名称或类别，保存时按最终名称和类别归档主图；原图保留供其他商品使用。图片路径保存为相对于数据目录的路径，便携版数据目录是程序所在目录，开发版是 Electron 的 userData 目录。详情相册新增、替换图片也使用同一目录规则。

## 下载公开版

[GitHub Releases](https://github.com/matt-xb/guolong-sales-tool/releases) 提供 Windows x64 便携 ZIP。解压到自己的可写目录，运行 `GuolongSalesTool.exe`，无需安装 Node.js。首次运行创建空数据库，程序包不含公司产品或业务资料。

数据库、图片和导出文件保存在解压目录，升级前备份自己的数据，不要将公开版解压覆盖公司版目录。首次发行标为预发布，尚未完成干净电脑和界面人工验收；程序未签名。

## 运行

安装 Node.js 后执行：

```powershell
npm ci
npm start
```

首次运行创建空数据库，需要自行录入产品。公开版使用独立的 Electron 应用名，不读取公司版的用户数据目录。

```powershell
npm test
```

测试只使用临时空数据库和虚构产品，不依赖公司产品库。

在 Windows 上运行 `npm run package` 生成对应版本的 `dist/guolong-sales-v<version>-public-windows-x64`；打包脚本只复制公开源码和清理后的模板，并在独立目录安装生产依赖、运行空库与模板导出检查。输出目录已存在时会停止，防止覆盖其中的使用数据。

## 同一源码构建公司版

默认 `npm run package` 只构建公开空库版。公司版使用私有输入目录，输出必须是全新目录：

```powershell
npm run package -- --company-content <private-distribution> --data-root <private-catalog> --output <new-output>
```

私有分发目录提供 `edition.json`（仅 updateSource、shareUser、videoScript）、四份 `templates/*.xlsx`，以及可选的 `branding`、`tools`、`release-notes.json`。私有资料目录提供 `data/seed-sales.sqlite`、`images`、`materials`；不传 `--data-root` 时使用私有分发目录。密码不接受 JSON 配置，只读取 `SALES_SHARE_PASSWORD`，公司版兼容 `GUOLONG_SHARE_PASS`。

公司包使用原应用名和标识，公开包保留独立身份。两种包的业务源码完全相同；公司包在打包时载入私有模板和品牌资源。运行代码位于 `resources/app`，不再依赖旧私有源码打 ASAR 的流程。公司包不得上传到公开 Release。

本次只验证迁移构建，未升级任何现用程序或发布新 Release。正式分发仍需正常递增版本并验收升级。

## 可选局域网功能

### 增量更新与资料刷新

2.22.0 起，软件升级和资料刷新共用 `sync-manifest.json`。发布端生成 SHA-256 文件清单；接收端按内容比较，只从共享源下载新增或改变的文件，不受重新打包的修改时间影响。没变的文件从本机复用，并在应用前再次校验。更新窗口显示文件下载量和本机复用数量。

资料刷新同步数据库、图片、资料，源端删除的公共文件仍会同步删除；源端未提供 materials 时保留本机资料。无清单的旧共享源支持一次完整资料刷新的兼容模式。程序升级要求完整、版本一致的新目录和有效清单，下载校验后由隐藏的 Windows 安装步骤等旧程序退出再替换；安装失败恢复原文件，恢复失败保留备份并停止自动打开。程序自身不再调用 update.bat/cmd 完成升级。

Windows 程序升级使用系统脚本宿主隐藏启动 PowerShell，并在安装器确认就绪后才退出原程序；若系统策略禁用了脚本宿主，更新会提示失败且不修改原程序。旧版需要完整升级一次到 2.22.0，之后的软件升级和资料刷新才使用这个增量入口。

合同/报价单输出、最近文件与本机设置、备份、更新源配置、Git/编辑器元数据、凭据及运行日志不参与覆盖或清理。软件升级仍会同步公共产品数据库与资料，现有镜像行为保持。此功能连接已配置的局域网文件共享，不从 GitHub Release 自动下载；手动下载完整 ZIP 仍是全包下载。

打包时自动生成清单。便携版运行时会监视目录内的文件变化并更新清单，数据库/库存/照片变更会自动发布；仅变更文件重新计算校验值。软件关闭期间手动改文件后，应打开发布端软件等清单生成完成，或在有 Node.js 的维护机运行 `node scripts/publish-sync-manifest.js <分发目录>`。清单不能提交到公开仓库，因为它包含实际分发文件名称；它没有鉴权签名，信任边界沿用已授权的共享源和共享账户权限。

旧版需先完整升级一次到2.22.0。后续无需按旧版本分别制作补丁，接收端直接与当前共享清单比较。

局域网更新与售后视频只连接用户自行配置的服务；未设置时不会使用公司的默认共享盘。

- `SALES_UPDATE_SOURCE`：自己的更新共享目录，也可用本机 `update-source.txt` 指定。
- `SALES_SHARE_USER` / `SALES_SHARE_PASSWORD`：需要认证时从运行环境提供；不要提交密码或本机配置。
- `SALES_VIDEO_URL`：自己的售后视频服务地址。
- `SALES_VIDEO_SCRIPT`：可选的本机视频启动脚本。

现有公司版私有仓库和程序包继续保留。本公开仓库不分发包含公司产品资料的安装包。

## 操作日志与故障排查（2026-10-13）

便携版日志在程序目录 `local-data/logs/operations.log`；开发版在 Electron 的 `userData/local-data/logs/operations.log`。

覆盖启动/数据库初始化、产品保存与删除、合同/报价生成、库存应用、图片和资料修改/复制、售后入口、更新启动以及资料刷新的阶段结果。IPC 操作同一 `id` 关联开始与返回；`handler_returned` 表示处理函数返回，不代替外部浏览器、系统安装器或粘贴的实际验收。取消/无结果为 `skipped`；模板缺失为 `TEMPLATE_MISSING`。`data-refresh:start` 是请求，`data-refresh` 是后台刷新事务，分别有编号，后者记录阶段和恢复要求。

出现“没反应”时，先保留发生时间和最后一个操作编号，再查看对应的阶段、结果、错误类型/代码。可用 PowerShell `Get-Content .\local-data\logs\operations.log -Tail 80` 查看便携版末尾记录。

每份新操作日志约 1 MiB，保留当前文件及 `.1`～`.3` 三份轮换文件，约 4 MiB；时间使用 UTC。日志仅记录操作标签、编号、阶段、结果、计数和耗时，不记录业务正文、凭据、客户名称、文件路径或请求参数。异常记录类型或固定错误码，具体提示仍在原界面显示。磁盘不可写时诊断失败不阻断业务，因此缺少记录不能单独证明操作没有发生。

后续维护：涉及这些操作的改动，同时核对开始、成功/取消/跳过/失败的去向；提前返回写明固定原因。新增记录不得直接序列化参数、返回正文或异常全文。完成相关验证后更新本项目权威 handoff，使用说明变化时更新本节。源码及测试可随项目同步，实际日志不提交、不进入分发包。

本节对应 2026-10-13 的源码维护，现有下载包与运行进程尚未升级；新日志从使用更新源码构建的程序开始产生。旧版本不会凭空补出历史记录。
